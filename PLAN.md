# Traffic Quality Lab — общий план

Полностью синтетический стенд «рекламная кампания → сайт → Метрика → отчёт».
Никаких данных клиентов Okkam: сайт свой, трафик свой, логи DSP и Верификатора генерируются.

## Идея

Мы сами управляем трафиком, поэтому знаем правду: сколько кликов было «отправлено»,
сколько дошло, где вшита аномалия. Пайплайн анализа должен найти ровно эти аномалии —
это проверяется тестами.

## Архитектура

```
[Симулятор кампании]  ──►  dsp_clicks.csv          (клики DSP по дням, SSP, площадкам)
        │              ──►  verifier_export.csv     (формат «как у Верификатора»: Кликов всего, IVT)
        │
        ▼
[Бот-посетитель Playwright] ── визиты с UTM ──► [Сайт-витрина на GitHub Pages]
                                                     │  GTM: события (клик по кнопке,
                                                     │  скролл 50%, корзина, форма)
                                                     ▼
                                              [Яндекс Метрика: свой счётчик]
                                                     │  Reporting API / Logs API
                                                     ▼
                                   [Python: выгрузка → DuckDB → чистка → анализ]
                                                     │        └─ тот же расчёт на SQL + сверка
                                                     ▼
                                   [Google Sheets / Excel с подсветкой, README-выводы]
```

## Компоненты

### 1. Сайт-витрина (`site/`)
- Статичный «магазин» на GitHub Pages: главная, каталог, карточка, корзина, форма заявки.
- Контейнер GTM: теги Метрики + события-цели:
  - `add_to_cart`, `form_submit`, `scroll_50`, `click_phone`.
- Счётчик Метрики с Вебвизором (можно показать кейс «пустой Вебвизор»).

### 2. Симулятор кампании (`src/simulate/campaign.py`)
- Задаёт план: даты, SSP (`ssp_a`, `ssp_b`, `ssp_c`), площадки, бюджет кликов в день.
- Пишет `dsp_clicks.csv` и `verifier_export.csv` (DSP-показатель «Кликов всего с учётом IVT», доля GIVT/SIVT).
- Сценарии аномалий (config `scenarios.yaml`):
  - провал доходимости по `ssp_b` 3 дня подряд;
  - высокий GIVT по одной площадке;
  - конверсии без визитов (аномальные цели);
  - дубли строк и пропущенная дата в выгрузке;
  - UTM в разном регистре / с мусорным хвостом.
- Сохраняет `ground_truth.json` — что именно вшито.

### 3. Бот-посетитель (`src/simulate/visitor.py`)
- Playwright читает план из симулятора и делает визиты на сайт с UTM.
- Поведение по профилям: «отказ», «листает каталог», «кладёт в корзину», «оставляет заявку».
- Доходимость задаётся явно: из N кликов DSP реально открываем M визитов.
- Запуск: GitHub Actions по расписанию, малый объём (десятки–сотни визитов в день).
- Важно: визиты с IP датацентра и headless-браузера Метрика частично пометит как роботов —
  это используем как кейс «роботность», а не прячем.

### 4. Выгрузка (`src/extract/`, `apps_script/`)
- Python-клиент Reporting API + Logs API Метрики, токен только в `.env`.
- Apps Script — версия `metrika_universal.gs` для выгрузки в Google Sheets.
- Режим `--offline`: всё из локальных CSV, чтобы репо работал без доступа к счётчику.

### 5. Чистка и анализ (`src/clean/`, `src/analysis/`)
- Чистка: дубли, таймзона, пропуски дат, нормализация UTM, отчёт о чистке.
- Доходимость по дням и за период: визиты / клики DSP, визиты / клики Верификатора; расхождения в %, средние, сверка с «Итого».
- PI по срезам (SSP, площадка, устройство).
- Временные ряды: скользящее среднее, STL, z-score / IQR, changepoint (`ruptures`).
- Конверсии: CR + интервал Уилсона, хи-квадрат между SSP.

### 6. SQL-дубль (`sql/`)
- Те же метрики: CTE, `LAG`, `AVG() OVER`, `ROW_NUMBER` для дублей.
- `tests/test_python_vs_sql.py` — цифры совпадают.
- `tests/test_ground_truth.py` — найдены все аномалии из `ground_truth.json`.

### 7. Отчёт (`src/report/`)
- Google Sheets через gspread + условное форматирование (красный — ниже порога доходимости, жёлтый — отклонение от среднего > N%).
- Excel через openpyxl с теми же правилами.
- Опционально Streamlit.

## Этапы

| # | Что | Результат | Статус |
|---|-----|-----------|---|
| 1 | Сайт + GTM + счётчик Метрики | события видны в отладчике GTM и в Метрике | код готов, нужен счётчик и контейнер |
| 2 | Симулятор кампании + ground truth | CSV DSP и Верификатора | готово |
| 3 | Бот-посетитель + Actions по расписанию | визиты с UTM копятся в Метрике | код готов, нужен счётчик и контейнер |
| 4 | Выгрузка API + DuckDB | raw-слой | офлайн готово; API-клиент не проверен на живом счётчике |
| 5 | Чистка + доходимость pandas и SQL + тест сверки | marts-слой | готово |
| 6 | Временные ряды, аномалии, конверсии | тест на ground truth зелёный | готово |
| 7 | Отчёт в Sheets/Excel, README со скриншотами | готово к показу | Excel готово; выгрузка в Sheets не проверена без сервисного аккаунта |

## Что учесть

- Ничего из реальных задач Okkam: ни клиентов, ни UTM подрядчиков, ни цифр.
- Токены Метрики и ключ сервисного аккаунта Google — только в `.env` / GitHub Secrets.
- Объём искусственного трафика держим маленьким: это свой тестовый счётчик, задача — показать пайплайн.
